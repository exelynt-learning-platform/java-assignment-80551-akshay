# Assignment: Version Control Project using Git & GitHub

## 1. Objective

The objective of this assignment is to demonstrate practical knowledge of Git and GitHub by creating a version-controlled project, tracking file changes, managing branches, merging changes, and synchronizing the local repository with GitHub.

## 2. Project Structure

आपला project साधारण असा दिसेल:

GitBasics/

`README.md`

`index.txt`

`about.txt`

`.gitignore`

`.git/`

Git's internal repository data

## 3. Step 1 — Create or Verify the Local Repository

Open Terminal on your Mac.

जर मागील assignment मधील repository आधीपासून असेल, तर:

```
cd GitBasics
git status
```

जर नवीन project तयार करायचा असेल, तर:

```
mkdir GitBasics
cd GitBasics
git init
```

Verify the repository:

```
git branch
git log --oneline
```

जर repository मध्ये अजून commit नसेल, तर `git log` error दाखवू शकतो. पहिला commit झाल्यानंतर तो पुन्हा run कर.

## 4. Step 2 — Create Project Files

Create the required files if they do not already exist:

```
touch index.txt about.txt README.md .gitignore
```

Add sample content:

```
echo "Welcome to Git Basics" > index.txt
echo "This project demonstrates version control" > about.txt
```

Add the following content to `README.md` using your text editor:

# Version Control Project using Git & GitHub

## Project Overview

This project demonstrates the basic concepts of Git and GitHub.

## Objectives

- Create and manage a Git repository.
- Track changes using Git.
- Stage and commit files.
- Create and merge branches.
- Connect a local repository to GitHub.
- Push and pull changes from a remote repository.

## Technologies

- Git
- GitHub

## Conclusion

This project demonstrates how Git and GitHub help developers track code changes and collaborate on projects.

Add this to `.gitignore`:

```
.DS_Store
.env
node_modules/
```

Check the files:

```
ls -la
git status
```

Explanation: I created the project files and documented the purpose of the repository. The `.gitignore` file specifies files and directories that Git should ignore when they are untracked.

## 5. Step 3 — Stage and Commit Changes

Stage the files:

```
git add README.md index.txt about.txt .gitignore
```

Verify the staging area:

```
git status
```

Commit the changes:

```
git commit -m "Add initial project files and documentation"
```

Make another change:

```
echo "Git tracks changes in project files" >> index.txt
git diff
git add index.txt
git commit -m "Update Git basics introduction"
```

View the commit history:

```
git log --oneline
```

Explanation: I staged the project files, created meaningful commits, and used `git log --oneline` to view the commit history.

## 6. Step 4 — Create a Branch and Merge Changes

Ensure your main branch is named `main`:

```
git branch -M main
```

Create and switch to a feature branch:

```
git switch -c feature-documentation
```

Create a new file in the feature branch:

```
echo "This file was added using a feature branch" > feature.txt
git add feature.txt
git commit -m "Add feature branch documentation"
```

Switch back to `main`:

```
git switch main
```

Merge the feature branch:

```
git merge feature-documentation
```

Verify the result:

```
ls
git log --oneline --all --graph
git status
```

You should see `feature.txt` in the project directory, and the history should include the feature branch commit.

Explanation: I created a separate branch to make changes independently and merged those changes into `main`.

## 7. Step 5 — Connect the Repository to GitHub

Create a new repository on [GitHub](https://github.com/?utm_source=chatgpt.com) named `GitBasics`.

If you already connected the repository in a previous assignment, keep the existing remote. Otherwise, run the following command with your actual repository URL:

```
git remote add origin https://github.com/YOUR-USERNAME/GitBasics.git
```

Verify the remote configuration:

```
git remote -v
```

Push the main branch:

```
git push -u origin main
```

If you want to upload the feature branch too:

```
git push -u origin feature-documentation
```

Explanation: I connected the local repository to GitHub and pushed the committed changes to the remote repository.

## 8. Step 6 — Pull Updates from GitHub

To synchronize your local `main` branch with the remote repository, run:

```
git switch main
git pull origin main
```

Verify the repository status:

```
git status
```

If the remote repository has no new changes, Git may display `Already up to date.` This is a successful result.

Explanation: I used `git pull` to fetch and integrate updates from the remote repository into my local branch.

## 9. Step 7 — Final Verification

Run these commands:

```
git status
git remote -v
git branch
git log --oneline --all --graph
```

Expected results:

- `git status` shows a clean working tree if all changes are committed.
- `git remote -v` displays the GitHub repository URL.
- `git branch` displays the local branches.
- `git log --oneline --all --graph` displays the commit history and branch structure.
