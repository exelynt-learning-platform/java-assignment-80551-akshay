# Assignment: Tracking and Committing Changes in Git

Topic: Tracking Changes with Git

## 1. Objective

The objective of this assignment is to understand how Git tracks file changes, stages and commits changes, records meaningful commit messages, and displays commit history.

## 2. Create or Use an Existing Repository

तू मागच्या assignment मध्ये `GitBasics` folder तयार केला असेल, तर तोच वापर.

```
cd GitBasics
```

Check whether it is a Git repository:

```
git status
```

जर repository अजून तयार नसेल, तर हे commands वापर:

```
mkdir GitBasics
cd GitBasics
git init
```

## 3. Add at Least Two Files

Create two files:

```
touch index.txt
touch about.txt
```

Add content to the files:

```
echo "Welcome to Git Basics" > index.txt
echo "This project demonstrates Git version control" > about.txt
```

Verify the contents:

```
cat index.txt
cat about.txt
```

Explanation: I created two text files and added content to demonstrate how Git tracks changes in a project.

## 4. Stage and Commit Changes

### Step 1: Check the file status

```
git status
```

Git should display both files as untracked.

### Step 2: Stage the files

```
git add index.txt about.txt
```

Check the status again:

```
git status
```

Both files should now appear under `Changes to be committed`.

### Step 3: Commit the changes

```
git commit -m "Add initial project files"
```

Explanation: The `git add` command stages the files, while `git commit` saves the staged changes as a snapshot in the local repository.

## 5. Write Meaningful Commit Messages

A commit message should briefly explain what changed.

| Meaningful commit message    | Purpose                               |
| ---------------------------- | ------------------------------------- |
| `Add initial project files`  | Adds the first project files.         |
| `Update homepage content`    | Updates the homepage text or content. |
| `Add login validation tests` | Adds login validation tests.          |
| `Fix incorrect file content` | Corrects an issue in a file.          |

Avoid unclear messages such as `test`, `changes`, `update`, or `abc`, because they do not explain what was changed.

## 6. Make Another Change and Commit It

Append new content to `index.txt`:

```
echo "Git helps track project changes" >> index.txt
```

Check the changes:

```
git status
git diff
```

Stage and commit the update:

```
git add index.txt
git commit -m "Update Git introduction"
```

Now the repository contains two commits.

## 7. View Commit History

Run:

```
git log
```

This displays the commit history, including the commit hash, author, date, and commit message.

For a shorter history, use:

```
git log --oneline
```

Example output:

```
a1b2c3d Update Git introduction
e4f5g6h Add initial project files
```

The hashes shown above are examples; your actual hashes will be different.

## 8. Two Common Beginner Mistakes

Mistake 1: Forgetting to stage changes

Beginners sometimes modify a file and run `git commit` without running `git add` first.

Solution: Run `git status`, then stage the intended changes using `git ad filename` before committing.

Mistake 2: Writing unclear commit messages

Messages such as `update` or `test` do not clearly explain the changes.

Solution: Write short, meaningful messages, such as `Update Git introduction` or `Fix login validation`.
