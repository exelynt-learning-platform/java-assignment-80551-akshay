# Assignment: Collaborating on GitHub and Following Best Practices

## 1. Objective

The objective of this assignment is to create project documentation using `README.md`, configure a `.gitignore` file, follow the basic GitHub collaboration workflow, understand GitHub Issues and Pull Requests, and apply Git best practices for React projects.

## 2. Create a `README.md` File

Open Terminal and navigate to your project folder:

```
cd GitBasics
```

Create the README file:

```
touch README.md
```

Open the file in a text editor and add the following content.

# README.md

# GitHub Collaboration Project

## Project Overview

This project demonstrates the fundamentals of Git and GitHub, including version control, repository management, collaboration, and best practices.

## Objectives

- Track project changes using Git.
- Maintain project documentation using README.md.
- Ignore unnecessary files using .gitignore.
- Collaborate through GitHub Issues and Pull Requests.
- Follow best practices for project development.

## Technologies Used

- Git
- GitHub
- Markdown
- React (for React project best-practice examples)

## Git Commands Used

- `git init` – Initialize a repository.
- `git add` – Stage changes.
- `git commit` – Save changes in the local repository.
- `git push` – Upload commits to GitHub.
- `git pull` – Fetch and integrate remote changes.
- `git clone` – Copy a remote repository locally.

## Collaboration Workflow

1. Clone the repository.
2. Create a feature branch.
3. Make changes and commit them.
4. Push the feature branch to GitHub.
5. Create a Pull Request.
6. Review and merge approved changes.

## Conclusion

This project demonstrates how Git and GitHub help developers track changes, organize code, document projects, and collaborate efficiently.

Save the file as `README.md` in the root of your project.

## 3. Add a `.gitignore` File

A `.gitignore` file tells Git which untracked files and directories should not be added to version control.

Create the file:

```
touch .gitignore
```

For a React project using Node.js and npm, add these entries:

# Dependencies

node_modules/

# Production build

dist/\
build/

# Environment variables and secrets

.env\
.env.local\
.env.\*.local

# Debug logs

npm-debug.log\*\
yarn-debug.log\*\
pnpm-debug.log\*

# Operating system files

.DS_Store

# IDE settings

.vscode/\
.idea/

Important: Do not ignore files that the team needs to build the project, such as `package.json` or the appropriate lockfile (`package-lock.json`, `yarn.lock`, or `pnpm-lock.yaml`). Keep secrets and API keys out of Git.

## 4. Follow the Basic GitHub Workflow

Run these commands in your project directory:

```
git status
git add README.md .gitignore
git commit -m "Add project documentation and gitignore"
```

Create a feature branch for future work:

```
git switch -c feature/project-documentation
```

Push the branch to GitHub:

```
git push -u origin feature/project-documentation
```

Then open your GitHub repository, create a Pull Request, review the changes, and merge it when appropriate.

If your `README.md` or `.gitignore` has already been committed, Git will report that there is nothing new to commit. That is normal.

GitHub Issues

GitHub Issues are used to report bugs, suggest features, track tasks, and discuss project improvements.

Example: Create an issue titled `Fix login validation error` and describe the steps needed to reproduce the problem.

GitHub Pull Requests (PRs)

A Pull Request proposes merging changes from one branch into another. Team members can review the code, comment on changes, request improvements, and approve the work.

Example: Create a Pull Request titled `Add login validation` to merge the feature branch into `main`.

Difference: An Issue tracks work that needs to be done; a Pull Request proposes code changes for review and merging.

## 6. Git Best Practices for React Projects

| Best practice                                  | Explanation                                                                                        |
| ---------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| Use feature branches                           | Develop each feature separately from `main`.                                                       |
| Write meaningful commits                       | Use messages such as `Fix login form validation`.                                                  |
| Maintain a README                              | Document setup instructions, scripts, and project details.                                         |
| Use `.gitignore`                               | Exclude `node_modules`, build output, and local environment files.                                 |
| Protect secrets                                | Never commit passwords, private keys, or API credentials.                                          |
| Review Pull Requests                           | Check code quality and correctness before merging.                                                 |
| Keep dependencies reproducible                 | Commit `package.json` and the appropriate lockfile.                                                |
| Use consistent formatting                      | Follow the team's ESLint and Prettier rules where configured.                                      |
| Test before merging                            | Run available tests and build checks before approving changes.                                     |
| Avoid committing generated files unnecessarily | Usually exclude build artifacts and temporary files unless the project specifically requires them. |
